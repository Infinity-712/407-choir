# 两款小游戏整合

整合分支：`codex/integrate-minigames`，验证后以快进方式合入 `main`。基于当前网站 `e68e6f8`，合并：

- `codex/minigames` / `8f0369f`：抢凳子。
- `codex/minigames-color-war` / `20170a2`：颜色战争。

原有两条开发分支和工作树保留。网站模型、性能档位、手机精简底栏和全屏功能沿用当前网站版本。

## 入口与房间规则

常驻“派对游戏”入口提供两款游戏的选择与规则。桌面底栏仍为 7 个按钮，手机底栏仍为 4 个按钮。

每个房间同时容纳一款游戏：首次报名即占用游戏大厅；本局结束或所有报名者退出后可切换。上一款游戏的结算页面仍可查看，但另一款游戏已报名时不能重开、点名或更改旧局。退出与断线清理不受此限制。不同房间的游戏互不影响。

房间最多 20 人。抢凳子仍限 3–6 名参赛者；颜色战争为 2–20 人、五队、每队最多 4 人。未参赛者可以观战。

## 本地运行与验证

整合测试使用独立端口，避免误连其它工作树：

```powershell
$env:PORT = '3004'
$env:WEB_PORT = '5176'
npm test
npm run build
npm run test:browser
```

Playwright 默认自行启动服务，拒绝复用已占用端口。手动预览时在上述端口环境下执行 `npm run dev`；只有确认同一工作树的服务版本后，才可用 `PW_REUSE_SERVER=1` 复用服务进行测试。

本次重点验证跨游戏互斥、结算后切换、断线释放、真实布局的 20 人出生点，以及手机横竖屏的游戏入口、投掷与弹窗输入隔离。

验证记录：177 项单元与集成测试通过，21 个浏览器场景分批通过，生产构建通过。首次浏览器全套运行有一项在会话长时间中断后超时，已重新执行颜色战争完整流程；最终增补的桌面和手机切换流程验证了旧结算页面不能重开，但仍可以退出。手机竖屏投掷面板与互动提示的布局按实际截图修正。

房间 GLB 与现有互动布局未修改。GLB SHA-256：`01e7bcd2fde19bfcb1b31722cff91f041fa703f186759ab6d8e4cf4df22a12dd`。

20 台真实设备同场运行和语音的性能尚需实机测试；逻辑容量验证不能代替设备与网络压测。

## 后续开发与上线

继续开发前，应在各自工作树合入本整合提交，再开始下一项功能，避免重新引入旧版主界面。不要修改另一个对话的目录。

本次合并包含服务端协议和房间状态机变化。正式发布需要同时更新前端与房间服务；不能仅替换前端静态文件。服务端仍使用内存房间，更新重启会使在线用户重新连接，应安排合适的发布时间。既有 OpenClaw、证书续期和 TURN 服务不属于本次代码合并范围。
